# 4.5 Java 日誌寫入介面

- **情景說明**：本節透過兩個典型情景貫穿 Android 17 框架層 Java 日誌介面經 JNI 落地至 `liblog` 的完整呼叫鏈：
  1. **情景一（文字日誌）**：Java 應用程式呼叫 `Log.i`、`Log.e(tag, msg, tr)`、`Log.isLoggable` 與 `Log.wtf`，以及 `system_server` 系統服務呼叫 `Slog.w` / `Slog.wtf` 時，如何經由 `Log.println_native` / `Log.printlns` 與 `android_util_Log.cpp` 落地至 `liblog` 的 `__android_log_buf_write` 與 `__android_log_is_loggable`。
  2. **情景二（二進位事件日誌）**：系統元件透過 `EventLog.writeEvent` 寫入結構化二進位事件（含單一純量與 `Object...` 列表），以及診斷模組呼叫 `EventLog.readEvents` / `readEventsOnWrapping` 從 `logd` 讀回並反序列化為 `EventLog.Event`，同時透過 `getTagName` / `getTagCode` 查詢 `/system/etc/event-log-tags` 標籤對照表。
- **對應原書**：第 4 章 4.5 節〈Java日志写入接口〉（p.112–117，列表寫入解說延續至 p.118）
- **涉及專案與版本基準**：
  - `platform/frameworks/base` 〔`android-17.0.0_r1`，commit `94b4c163`〕
  - `platform/system/logging` 〔`android-17.0.0_r1`，commit `d35ba62`〕

## 4.5.1 情景一：`android.util.Log` 與 `android.util.Slog`（文字日誌寫入鏈）

> 對應原書 4.5 節〈android.util.Log〉與〈android.util.Slog〉（p.112–115）。在 Android 應用程式與 `system_server` 中，Java 層透過 `android.util.Log`（預設寫入 `LOG_ID_MAIN`）與 `android.util.Slog`（寫入 `LOG_ID_SYSTEM`）輸出文字日誌；兩者最終都匯聚到 `Log.println_native` 與 JNI 函式 `android_util_Log_println_native`，再交由 `liblog` 的 `__android_log_buf_write` 送往 `/dev/socket/logdw`。

**解說**：
1. `Log` 定義的 6 個優先級常數（`VERBOSE = 2` 至 `ASSERT = 7`）與 4.1 節 `liblog` 的 `android_LogPriority` 列舉值（`ANDROID_LOG_VERBOSE` 至 `ANDROID_LOG_FATAL`）一一對應。

> 1. 緩衝區常數新增 `LOG_ID_CRASH = 4`（用於未捕捉例外崩潰日誌），並提供 `@SystemApi` 方法 `logToRadioBuffer()` 寫入 `LOG_ID_RADIO`（註：原書 p.113 印刷將常數誤植為 `public static native int LOG_ID_MAIN = 0`，實際皆為 `public static final int`）。
> 2. 帶 `Throwable` 的 `v/d/i/w/e` 重載改走 `printlns()` 分段輸出，避免長堆疊追蹤超過單條 `LOGGER_ENTRY_MAX_PAYLOAD` 而遭到截斷。

### Step 2：長訊息與堆疊分段寫入：`Log.printlns`、`PreloadHolder` 與 `ImmediateLogWriter`

**位置**：`platform/frameworks/base/core/java/android/util/Log.java` 〔`android-17.0.0_r1`，lines 467–508, 581–629〕

```java
    public static int printlns(int bufID, int priority, @Nullable String tag, @NonNull String msg,
            @Nullable Throwable tr) {
        ImmediateLogWriter logWriter = new ImmediateLogWriter(bufID, priority, tag);
        // Acceptable buffer size. Get the native buffer size, subtract two zero terminators,
        // and the length of the tag.
        // Note: we implicitly accept possible truncation for Modified-UTF8 differences. It
        //       is too expensive to compute that ahead of time.
        int bufferSize = PreloadHolder.LOGGER_ENTRY_MAX_PAYLOAD    // Base.
                - 2                                                // Two terminators.
                - (tag != null ? tag.length() : 0)                 // Tag length.
                - 32;                                              // Some slack.
        // At least assume you can print *some* characters (tag is not too large).
        bufferSize = Math.max(bufferSize, 100);

        LineBreakBufferedWriter lbbw = new LineBreakBufferedWriter(logWriter, bufferSize);

        lbbw.println(msg);

        if (tr != null) {
            // This is to reduce the amount of log spew that apps do in the non-error
            // condition of the network being unavailable.
            Throwable t = tr;
            while (t != null) {
                if (t instanceof UnknownHostException) {
                    break;
                }
                if (t instanceof DeadSystemException) {
                    lbbw.println("DeadSystemException: The system died; "
                            + "earlier logs will point to the root cause");
                    break;
                }
                t = t.getCause();
            }
            if (t == null) {
                tr.printStackTrace(lbbw);
            }
        }

        lbbw.flush();

        return logWriter.getWritten();
    }
...
    static class PreloadHolder {
        public final static int LOGGER_ENTRY_MAX_PAYLOAD =
                logger_entry_max_payload_native();
    }

    private static class ImmediateLogWriter extends Writer {

        private int bufID;
        private int priority;
        private String tag;

        private int written = 0;

        public ImmediateLogWriter(int bufID, int priority, String tag) {
            this.bufID = bufID;
            this.priority = priority;
            this.tag = tag;
        }

        public int getWritten() {
            return written;
        }

        @Override
        public void write(char[] cbuf, int off, int len) {
            // Note: using String here has a bit of overhead as a Java object is created,
            //       but using the char[] directly is not easier, as it needs to be translated
            //       to a C char[] for logging.
            written += println_native(bufID, priority, tag, new String(cbuf, off, len));
        }

        @Override
        public void flush() {
            // Ignored.
        }

        @Override
        public void close() {
            // Ignored.
        }
    }
```

**解說**：
1. `PreloadHolder` 採用延遲初始化靜態內部類別，首次使用時僅呼叫一次 JNI `logger_entry_max_payload_native()`（回傳 `liblog` 的 `LOGGER_ENTRY_MAX_PAYLOAD`，即 4068 bytes）並快取，避免每次寫日誌都跨 JNI 查詢上限。
2. `printlns()` 扣除兩個 NUL 終止字元、tag 長度與 32 bytes 餘裕後（下限 100），建立 `LineBreakBufferedWriter` 包裝 `ImmediateLogWriter`；當訊息或堆疊追蹤過長時，會優先在換行符號邊界切分成多塊，每塊透過 `ImmediateLogWriter.write()` 呼叫一次 `println_native()` 並累加回傳的寫入位元組數。
3. 對於例外鏈（`getCause()`）：若包含 `UnknownHostException`（無網路屬常態），直接略過堆疊印出以減少雜訊；若包含 `DeadSystemException`，只印出一行精簡提示而不展開完整堆疊。

> 〔與 2.3 差異〕**新增**（原書 p.112–113）：Android 2.3 的 `Log` 並無 `printlns()`、`PreloadHolder` 與 `LineBreakBufferedWriter` 分段機制，帶 `Throwable` 的重載僅以 `msg + '\n' + getStackTraceString(tr)` 單次呼叫 `println_native()`，超長堆疊會在底層被截斷。

```cpp
int __android_log_is_loggable_len(int prio, const char* tag, size_t len, int default_prio) {
  int minimum_log_priority = __android_log_get_minimum_priority();
  int property_log_level = __android_log_level(tag, len);

  if (property_log_level >= 0 && minimum_log_priority != ANDROID_LOG_DEFAULT) {
    return prio >= std::min(property_log_level, minimum_log_priority);
  } else if (property_log_level >= 0) {
    return prio >= property_log_level;
  } else if (minimum_log_priority != ANDROID_LOG_DEFAULT) {
    return prio >= minimum_log_priority;
  } else {
    return prio >= default_prio;
  }
}

int __android_log_is_loggable(int prio, const char* tag, int default_prio) {
  auto len = tag ? strlen(tag) : 0;
  return __android_log_is_loggable_len(prio, tag, len, default_prio);
}
```

**解說**：
1. **`@FastNative` 最佳化**：`Log.isLoggable` 常放在熱路徑的 `if (Log.isLoggable(TAG, Log.DEBUG))` 守衛條件裡，標註 `dalvik.annotation.optimization.FastNative` 後，ART 在呼叫此 JNI 方法時省略標準執行緒狀態切換（`Runnable` ↔ `Native`）與完整的 JNI 進出開銷，大幅降低高頻檢查的延遲。
2. **23 字元 tag 限制已移除**：早期 Android（API ≤ 25，Nougat 7.0 及以前）受限於舊系統屬性名稱長度上限 `PROP_NAME_MAX`（32 bytes，扣除 `"log.tag."` 8 bytes 與 NUL 僅剩 23 字元），`android_util_Log_isLoggable` 會在 tag 超過 23 字元時拋出 `IllegalArgumentException`。從 Android 17 的 `android_util_Log_isLoggable` 與 `Log.java` Javadoc（lines 248–250）可見，此長度檢查已完全移除，直接呼叫 `liblog` 的 `__android_log_is_loggable(level, tag, ANDROID_LOG_INFO)` → `__android_log_is_loggable_len(...)`。
3. **底層查詢順序**：`properties.cpp` 的 `__android_log_level()` 依序查詢四個系統屬性：`persist.log.tag.<tag>` → `log.tag.<tag>` → `persist.log.tag` → `log.tag`，並搭配 `__system_property_area_serial()` 單層快取（以 `pthread_mutex_trylock` 避免訊號處理常式死鎖）；若四個屬性皆未設定且未覆寫行程最小層級，則以預設值 `ANDROID_LOG_INFO`（4）比較。
4. `android_util_Log.h` 另匯出 `android_util_Log_isVerboseLogEnabled(const char* tag)`，供 `libandroid_runtime` 內部其他 JNI 模組直接檢查某個 tag 是否開啟了 `VERBOSE` 日誌。

> 〔與 2.3 差異〕**邏輯改變**（原書 p.112–114）：Android 2.3 的 `android_util_Log_isLoggable` 直接在 JNI 層呼叫 `property_get("log.tag.<tag>", ...)` 並硬性限制 tag 長度不可超過 23 字元（否則拋出 `IllegalArgumentException`），且尚未引入 ART 的 `@FastNative`；Android 17 改由 `@FastNative` 委派至 `liblog` 的 `__android_log_is_loggable`（支援 `persist.log.tag.*` 與全域 `log.tag`，並搭配序號快取），且已解除 23 字元 tag 長度限制。

**解說**：
1. **寫入層級是 `ERROR` 而非 `ASSERT`**：儘管 Javadoc 歷史文案提及 `ASSERT`，Android 17 的 `Log.wtf()` 實作（line 343）刻意以 `Log.ERROR` 呼叫 `printlns(logId, ERROR, ...)`，並在註解中明確指出 `ASSERT` 保留給必然中止行程的情境，而 `onTerribleFailure` 不一定會終止行程。
2. **緩衝區分流與 `system` 旗標**：
   - `Log.wtf()` 傳入 `logId = LOG_ID_MAIN`、`system = false`；
   - `Slog.wtf()`（見下一個 Step）傳入 `logId = LOG_ID_SYSTEM`、`system = true`；
   - `wtfStack()` 將 `localStack` 設為 `true`，使 `printlns` 印出新建立的 `TerribleFailure what` 捕捉到的當前呼叫端堆疊；`wtfQuiet()` 則略過 `printlns` 僅上報 `sWtfHandler`。
3. **上報與中止決策**：預設 `sWtfHandler` 透過 `RuntimeInit.wtf()` 經由 Binder 呼叫 `ActivityManagerService.handleApplicationWtf()`（開機早期 AMS 尚未就緒時退回 `sDefaultApplicationWtfHandler` 或 `Slog.e`），由系統依據 `Settings.Global.WTF_IS_FATAL` 等策略決定寫入 `DropBoxManager` 與是否回傳 `exit = true`；只有在回傳 `true` 時，行程才會自我終止（`Process.killProcess` + `System.exit(10)`）。測試環境亦可透過 `Log.setWtfHandler()` 替換 `sWtfHandler`。
4. **`LOG_ID_CRASH` 的實際去向**：須注意 `Log.wtf()` 寫入的是 `LOG_ID_MAIN`（或 `Slog.wtf()` 的 `LOG_ID_SYSTEM`），而非 `LOG_ID_CRASH`。`Log.LOG_ID_CRASH` 主要由 `RuntimeInit.Clog_e()` 使用，當行程出現未捕捉例外（`LoggingHandler.uncaughtException()` / `logUncaught()`）時，透過 `Log.printlns(Log.LOG_ID_CRASH, Log.ERROR, ...)` 寫入獨立的 `crash` 緩衝區，避免被大量 `main` 日誌沖刷。

> 〔與 2.3 差異〕**新增 + 邏輯改變**（原書 p.112–114）：原書 4.5 節未涵蓋 `Log.wtf()` 與 `LOG_ID_CRASH`；Android 2.3 剛引入 `wtf` 時曾以 `ASSERT` 層級輸出，Android 17 改為 `ERROR` 層級、支援 `wtfStack`/`wtfQuiet`、區分 `system` 參數避免 `system_server` 同步崩潰，並新增獨立的 `LOG_ID_CRASH` 緩衝區供 `RuntimeInit.Clog_e` 記錄致命例外。

```java
    @android.ravenwood.annotation.RavenwoodReplace
    private static synchronized void readTagsFile() {
        if (sTagCodes != null && sTagNames != null) return;

        sTagCodes = new HashMap<String, Integer>();
        sTagNames = new HashMap<Integer, String>();

        Pattern comment = Pattern.compile(COMMENT_PATTERN);
        Pattern tag = Pattern.compile(TAG_PATTERN);
        BufferedReader reader = null;
        String line;

        try {
            reader = new BufferedReader(new FileReader(TAGS_FILE), 256);
            while ((line = reader.readLine()) != null) {
                if (comment.matcher(line).matches()) continue;

                Matcher m = tag.matcher(line);
                if (!m.matches()) {
                    Log.wtf(TAG, "Bad entry in " + TAGS_FILE + ": " + line);
                    continue;
                }

                try {
                    int num = Integer.parseInt(m.group(1));
                    String name = m.group(2);
                    registerTagLocked(num, name);
                } catch (NumberFormatException e) {
                    Log.wtf(TAG, "Error in " + TAGS_FILE + ": " + line, e);
                }
            }
        } catch (IOException e) {
            Log.wtf(TAG, "Error reading " + TAGS_FILE, e);
            // Leave the maps existing but unpopulated
        } finally {
            try { if (reader != null) reader.close(); } catch (IOException e) {}
        }
    }

    private static void registerTagLocked(int num, String name) {
        sTagCodes.put(name, num);
        sTagNames.put(num, name);
    }
```

```cpp
    static jint writeEventFloat(JNIEnv* env ATTRIBUTE_UNUSED, jobject clazz ATTRIBUTE_UNUSED,
            jint tag, jfloat value) {
        android_log_event_list ctx(tag);
        ctx << (float)value;
        return ctx.write(LogID);
    }
    static jint writeEventString(JNIEnv* env, jobject clazz ATTRIBUTE_UNUSED, jint tag,
            jstring value) {
        android_log_event_list ctx(tag);
        // Don't throw NPE -- I feel like it's sort of mean for a logging function
        // to be all crashy if you pass in NULL -- but make the NULL value explicit.
        ctx << (value != nullptr ? ScopedUtfChars(env, value).c_str() : "NULL");
        return ctx.write(LogID);
    }
    static jint writeEventArray(JNIEnv* env, jobject clazz ATTRIBUTE_UNUSED, jint tag,
            jobjectArray value) {
        android_log_event_list ctx(tag);

        if (value == nullptr) {
            ctx << "[NULL]";
            return ctx.write(LogID);
        }

        jsize copied = 0, num = env->GetArrayLength(value);
        for (; copied < num && copied < 255; ++copied) {
            if (ctx.status()) break;
            ScopedLocalRef<jobject> item(env, env->GetObjectArrayElement(value, copied));
            if (item == nullptr) {
                ctx << "NULL";
            } else if (env->IsInstanceOf(item.get(), gStringClass)) {
                ctx << ScopedUtfChars(env, (jstring) item.get()).c_str();
            } else if (env->IsInstanceOf(item.get(), gIntegerClass)) {
                ctx << (int32_t)env->GetIntField(item.get(), gIntegerValueID);
            } else if (env->IsInstanceOf(item.get(), gLongClass)) {
                ctx << (int64_t)env->GetLongField(item.get(), gLongValueID);
            } else if (env->IsInstanceOf(item.get(), gFloatClass)) {
                ctx << (float)env->GetFloatField(item.get(), gFloatValueID);
            } else {
                jniThrowException(env,
                        "java/lang/IllegalArgumentException",
                        "Invalid payload item type");
                return -1;
            }
        }
        return ctx.write(LogID);
    }
```

```cpp
int android_log_write_list(android_log_context context, log_id_t id) {
  const char* msg;
  ssize_t len;

  if ((id != LOG_ID_EVENTS) && (id != LOG_ID_SECURITY) && (id != LOG_ID_STATS)) {
    return -EINVAL;
  }

  if (!context || (kAndroidLoggerWrite != context->read_write_flag)) {
    return -EBADF;
  }
  if (context->list_nest_depth) {
    return -EIO;
  }
  /* NB: if there was overflow, then log is truncated. Nothing reported */
  context->storage[1] = context->count[0];
  len = context->len = context->pos;
  msg = (const char*)context->storage;
  /* it's not a list */
  if (context->count[0] <= 1) {
    len -= sizeof(uint8_t) + sizeof(uint8_t);
    if (len < 0) {
      len = 0;
    }
    msg += sizeof(uint8_t) + sizeof(uint8_t);
  }
  return (id == LOG_ID_EVENTS)
             ? __android_log_bwrite(context->tag, msg, len)
             : ((id == LOG_ID_STATS) ? __android_log_stats_bwrite(context->tag, msg, len)
                                     : __android_log_security_bwrite(context->tag, msg, len));
}
```

**解說**：
1. **統一使用 RAII 封裝 `android_log_event_list`**：無論是單一純量（`int`/`long`/`float`/`String`）或變長陣列（`Object...`），JNI 層都不再手動拼裝位元組陣列，而是建立區域變數 `android_log_event_list ctx(tag)`，透過重載的 `operator<<` 寫入各欄位，最後呼叫 `ctx.write(LogID)`，離開作用域時由解構子自動呼叫 `android_log_destroy(&ctx)` 清除並釋放緩衝區。
2. **單元素自動剝除列表標頭**：`create_android_logger(tag)` 初始化時會在 `storage[0..1]` 預留 2 bytes 的 `android_event_list_t`（`EVENT_TYPE_LIST` + 元素計數）。當 `android_log_write_list()` 送出時，若頂層元素數量 `context->count[0] <= 1`，便會將指標 `msg` 往後移 2 bytes、長度減 2，直接以單一型別（例如 `EVENT_TYPE_INT` / `EVENT_TYPE_STRING`）送出；只有在元素數量 ≥ 2 時才保留外層 `EVENT_TYPE_LIST` 標頭。因此 `writeEventInteger` 等單值介面與 `writeEventArray` 得以共用同一套編碼器。
3. **空值與非法型別處理**：
   - `writeEventString` 遇到 `value == nullptr` 時不拋 NPE，而是明確寫入字面字串 `"NULL"`；
   - `writeEventArray` 遇到陣列本身為 `nullptr` 時寫入 `"[NULL]"`（註：2.3 曾轉交 `writeEventString` 寫入 `"NULL"`）；
   - 迴圈上限仍為 255 個元素（受 `EVENT_TYPE_LIST` 單一位元組計數限制），若中途 `ctx.status()` 回報溢位或錯誤則提前 `break` 截斷；若元素既非 `null`，也不是 `String`、`Integer`、`Long`、`Float` 其中之一，則拋出 `IllegalArgumentException` 並回傳 `-1`（此時未呼叫 `ctx.write()`，事件不會寫出）。
4. **落地至 `liblog`**：`android_log_write_list()` 針對 `LOG_ID_EVENTS` 呼叫 `__android_log_bwrite(context->tag, msg, len)`（見 4.4 節 `log_event_write.cpp`），由 `liblog` 補上 4-byte `tag` 後送往 `logd`。

> 〔與 2.3 差異〕**邏輯改變 + 新增**（原書 p.115–118）：
> 1. Android 2.3 在 JNI 層針對 `int`/`long` 呼叫 `android_btWriteLog`，針對 `String`/`Object...` 則在棧上宣告 `uint8_t buf[MAX_EVENT_PAYLOAD]` 手動 `memcpy` 拼裝，並在結尾手動補上 `'\n'` 終止字元再呼叫 `android_bWriteLog`；Android 17 全部改由 `liblog` 的 `android_log_event_list` 統一編碼並呼叫 `__android_log_bwrite`，不再於有效負載末尾手動附加 `'\n'`。
> 2. 新增 `Float`（`EVENT_TYPE_FLOAT = 4`）支援，涵蓋獨立重載 `writeEventFloat` 與 `writeEventArray` 中的 `java.lang.Float` 拆箱。
> 3. `writeEventArray` 傳入 `null` 陣列時由原本寫入 `"NULL"` 改為寫入 `"[NULL]"`；使用 `ScopedLocalRef` / `ScopedUtfChars` 自動管理 JNI 區域參照與字串釋放。

```cpp
    static void readEvents(JNIEnv* env, int loggerMode, jintArray jTags, jlong startTime,
            jobject out) {
        std::unique_ptr<struct logger_list, decltype(&android_logger_list_close)> logger_list(
                nullptr, android_logger_list_close);
        if (startTime) {
            logger_list.reset(android_logger_list_alloc_time(loggerMode,
                    log_time(startTime / NS_PER_SEC, startTime % NS_PER_SEC), 0));
        } else {
            logger_list.reset(android_logger_list_alloc(loggerMode, 0, 0));
        }
        if (!logger_list) {
            jniThrowIOException(env, errno);
            return;
        }

        if (!android_logger_open(logger_list.get(), LogID)) {
            jniThrowIOException(env, errno);
            return;
        }

        ScopedIntArrayRO tags(env);
        if (jTags != nullptr) {
            tags.reset(jTags);
        }

        while (1) {
            log_msg log_msg;
            int ret = android_logger_list_read(logger_list.get(), &log_msg);

            if (ret == 0) {
                return;
            }
            if (ret < 0) {
                if (ret == -EINTR) {
                    continue;
                }
                if (ret == -EINVAL) {
                    jniThrowException(env, "java/io/IOException", "Event too short");
                } else if (ret != -EAGAIN) {
                    jniThrowIOException(env, -ret);  // Will throw on return
                }
                return;
            }

            if (log_msg.id() != LogID) {
                continue;
            }

            int32_t tag = * (int32_t *) log_msg.msg();

            if (jTags != nullptr) {
                bool found = false;
                for (size_t i = 0; !found && i < tags.size(); ++i) {
                    found = (tag == tags[i]);
                }
                if (!found) {
                    continue;
                }
            }

            jsize len = ret;
            ScopedLocalRef<jbyteArray> array(env, env->NewByteArray(len));
            if (array == nullptr) {
                return;
            }

            {
                ScopedByteArrayRW bytes(env, array.get());
                memcpy(bytes.get(), log_msg.buf, len);
            }

            ScopedLocalRef<jobject> event(env,
                    env->NewObject(gEventClass, gEventInitID, array.get()));
            if (event == nullptr) {
                return;
            }

            env->CallBooleanMethod(out, gCollectionAddID, event.get());
            if (env->ExceptionCheck() == JNI_TRUE) {
                return;
            }
        }
    }
```

**解說**：
1. **建立 `liblog` 讀取器**：`EventLogHelper::readEvents` 使用自訂刪除器 `android_logger_list_close` 的 `std::unique_ptr` 管理 `struct logger_list`。若 `startTime != 0`（如 `readEventsOnWrapping`），呼叫 `android_logger_list_alloc_time()` 並將奈秒時間戳拆分為 `(sec, nsec)`；否則呼叫 `android_logger_list_alloc()`。接著透過 `android_logger_open(logger_list.get(), LogID)` 指定只讀取 `LOG_ID_EVENTS`（底層連線 `/dev/socket/logdr` 並由 `logd` 檢查權限與 UID 範圍，詳見 4.2 與 4.3 節）。
2. **串流讀取與錯誤處理**：在 `while (1)` 迴圈內反覆呼叫 `android_logger_list_read(logger_list.get(), &log_msg)`：
   - `ret == 0`：串流結束，正常返回；
   - `ret == -EINTR`：遭訊號中斷，繼續重試；
   - `ret == -EAGAIN`：因設定了 `ANDROID_LOG_NONBLOCK`，表示目前已無更多可讀日誌，安靜結束返回；
   - `ret == -EINVAL` 或其他負值錯誤碼：透過 `jniThrowException` / `jniThrowIOException` 拋出 `IOException`。
3. **Tag 過濾與建構 Java `Event` 物件**：
   - 驗證 `log_msg.id() == LogID` 後，直接讀取有效負載前 4 bytes 作為事件 `tag`（`*(int32_t *) log_msg.msg()`），與 Java 傳入的 `tags[]` 逐一比對過濾；
   - 命中後配置長度為 `ret` 的 `jbyteArray`，將**整塊原始 `log_msg.buf`**（包含完整的 v4 `struct logger_entry` 28-byte 標頭與後續有效負載）完整 `memcpy` 複製進陣列；
   - 透過預先快取的 `gEventInitID` 建構 `EventLog$Event(byte[])`，再呼叫 `Collection.add()` 加入 `out` 容器。

> 〔與 2.3 差異〕**新增 + 邏輯改變**（原書 p.115–118）：原書 4.5 節未涵蓋 `EventLog.readEvents`；在 Android 2.3 實作中，`readEvents` 是直接 `open("/dev/log/events", O_RDONLY | O_NONBLOCK)` 並以 `read()` 讀取核心驅動的 v1 `logger_entry`。Android 17 完全改由 `liblog` 的 `android_logger_list_alloc*` / `android_logger_open` / `android_logger_list_read` 透過 `/dev/socket/logdr` 向 `logd` 請求串流，並新增 `readEventsOnWrapping`（`ANDROID_LOG_WRAP`）。

**解說**：
1. **零拷貝檢視 `logger_entry` 標頭**：`Event(byte[] data)` 將 JNI 複製上來的原始位元組陣列包裝為 `ByteBuffer` 並設定為 `ByteOrder.nativeOrder()`（與本機 `logd` 產出的小端序一致）。所有偏移量常數（0/2/4/8/12/16/24）與 4.1 節 `struct logger_entry`（v4，28 bytes）完全對齊。
2. **向後相容的標頭長度計算**：`getHeaderSize()` 讀取偏移量 2 的 `hdr_size`（v4 中為 28）；若為 0（舊版 v1 的 `__pad` 欄位），則退回 `V1_PAYLOAD_START = 20`。`getUid()` 則以 `@SystemApi` 暴露偏移量 24 的 `uid` 欄位。

```mermaid
        Liblog->>Logd: 從 /dev/socket/logdr 讀取 logger_entry v4
        Logd-->>JNI: log_msg (header + tag + payload)
        JNI->>EventLog: new Event(byte[]) -> Collection.add(event)
    end
    App->>EventLog: event.getTag() / event.getData() -> decodeObject()
```

### 本節 2.3 → 17 核心演進速查

| 項目 | Android 2.3（原書 p.112–117） | Android 17（`android-17.0.0_r1`） |
|---|---|---|
| `Log` 緩衝區常數 | `MAIN`(0) / `RADIO`(1) / `EVENTS`(2) / `SYSTEM`(3) | 新增 `LOG_ID_CRASH`(4)（供 `RuntimeInit.Clog_e`）與 `@SystemApi logToRadioBuffer` |
| 帶 `Throwable` 的 `Log.*` | 字串拼接後單次呼叫 `println_native` | 改用 `printlns()` + `LineBreakBufferedWriter` 依 `LOGGER_ENTRY_MAX_PAYLOAD` 切行 |
| `Log.isLoggable` | JNI 直接讀 `log.tag.<tag>`，tag > 23 字元拋例外 | 標註 `@FastNative`，委派至 `liblog::__android_log_is_loggable`，解除 23 字元限制 |
| `Log.wtf` / `Slog.wtf` | 未在原書 4.5 節展開 | 以 `ERROR` 層級寫入，`sWtfHandler` 呼叫 `RuntimeInit.wtf` → AMS 決定是否終止；`Slog.wtf` 設 `system=true` 非同步上報 |
| `EventLog.writeEvent` | 4 種重載（無 `float`），JNI 手動拼裝 `buf` + 尾端 `'\n'` | 5 種重載（新增 `float`），抽離為模板 `EventLogHelper` + `liblog` `android_log_event_list` 統一編碼 |
